## 背景

平台自身、生成项目和执行环境承担不同职责。整体架构只需要说明谁保存事实、谁作出建议、谁执行副作用，具体接口、表结构、状态和资源限制由对应 Feature 维护。

## 摘要

- **主服务保存事实**：工作台与 API 围绕用户、项目、对话、产物、版本及任务状态工作。
- **Agent 提建议和产物**：Lead 与专业角色不直接获得宿主、数据库、发布或无限制工具权限。
- **执行边界分开**：固定构建／测试的共享执行服务与交互式 Vim 编辑沙箱是两种不同环境。

## V1 的主要关系

```text
浏览器工作台
    │ 请求、事件、预览；终端使用受控连接
    ▼
主服务：身份 / 对话与编排 / 产物 / 项目 Git / 版本与发布
    ├─ 模型服务：生成结构化决策与专业产物
    ├─ 共享执行服务：消费源码副本，返回构建、测试和校验证据
    └─ 编辑沙箱：仅当前编辑会话的受限 Vim 工作树
```

主服务是任务状态和项目事实的所有者，执行服务不挂载主服务数据卷，不持有业务密钥。V1 的共享执行服务是服务级隔离，不等于每用户、每任务的任意代码强沙箱。源码事实与可运行性分别由 [Feature 07](../features/05-产物与交付部署/07-通用源码与运行校验/README.md)定义，执行边界由 [Feature 06](../features/04-执行与验证环境/06-共享独立执行服务/README.md)定义。

编排、持久化事件与恢复属于 [Feature 11](../features/02-任务规划与执行编排/11-固定串行执行/README.md)；身份与所有权属于 [Feature 13](../features/03-用户交互与协作/13-账户与资源隔离/README.md)。一个合同被多个组件消费，仍只有一个 Feature 维护完整定义。

项目 Git 保存用户生成项目的源码历史；平台 GitHub 仓库保存平台自身代码和文档，两者不混用。版本与线上指针归 [Feature 12](../features/05-产物与交付部署/12-版本预览与发布/README.md)，交互式终端归 [Feature 15](../features/03-用户交互与协作/15-云端代码终端/README.md)。

## 部署与后续方向

V1 目标为 Railway 云端主服务与共享执行服务；启用 Vim 时另需符合隔离要求的编辑沙箱。配置、存储限制和运行步骤放在[平台运维](../operations/README.md)。具体环境与授权从[环境登记](../agents/validation-environments.md)读取，本文不宣称线上已完成验收。

V2 草案进一步拆分 Worker、持久化任务图、共享产物与任务级沙箱，分别见 [Feature 16](../features/02-任务规划与执行编排/16-任务图与多角色协作/README.md)和 [Feature 17](../features/04-执行与验证环境/17-任务级隔离与受控工具/README.md)。这些仍是 V1 验收后的后续方案，不能用目录迁移替代技术选型和验证。
