# 版本范围与整体验收

[toc]

- 更新日期：2026-09-29；性质：范围与依赖概览，不是实施计划或验收记录

## 背景

V1、V2 仍用于表达先后范围，但每项功能只在自己的 Feature 内维护。版本概览负责说明先交付什么、什么不能提前宣称完成，不重复功能细则。

## 摘要

- **V1**：先证明固定执行、持续修改、适用验证、版本和受控发布能够连成真实闭环。
- **V2**：V1 验收后评估动态任务图、局部并行、多角色返工与受控工具。
- **完成判断**：目录已建立、设计已确认、代码存在、已部署、已验证是不同事实。

## 整体验收

详细的跨 Feature 主路径、反路径和量化目标由 [Feature 11 的端到端验收](../features/02-任务规划与执行编排/11-固定串行执行/03-执行交互与整体验收.md)承接；单项验收和实际执行记录保留在负责的 Feature。V2 验收目标分别在 Feature 16、17，不能混入 V1 完成度。

发布前需要真实版本上的完整主路径、错误与恢复、多用户隔离、持久化和公开访问证据。代码中的单元测试或局部集成结果不能代替 Railway、编辑沙箱或浏览器的实际验证。
