## 执行迁移时的检查

1. 读取当前来源及其确认、代码和证据；与登记基线不同的修改按最新事实处理。
2. 完成一个来源的移动后更新本表、Feature 入口、设计索引和全部反向链接；删除旧位置的活动副本，不保留两个当前正文。只有用户授权实际移动时才执行。
3. 保留 Review、Bug 的稳定编号与证据位置；正文图片按实际引用关系处理，不为了目录对称机械搬动。
4. 检查 Markdown 本地链接、正文归属覆盖以及旧路径引用。已有断链和本次新增断链分别报告。
5. 第一批入口与规则、第二批正文迁移、后续 Feature 开发分别形成可审查提交；目录整理本身不表示业务功能已经交付。
