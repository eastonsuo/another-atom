# 能力域与 Feature 索引

本目录按五个能力域维护具体 Feature。每个 Feature 有产品说明；产品细则、技术合同、澄清、Spec、可选 Plan 和验证都放在该 Feature 内。`docs/design/` 仅保留[整体概览](../design/README.md)。

产品不再按 V1/V2 分期。选择具体 Feature 和实施范围后，按依赖与确认状态推进；产品确认、技术确认、实现、部署和验证分别记录，不能由文件位置或名称推断完成度。原有草案和未完成项不会因取消分期而自动获批。

## 文档位置与维护方式

| 材料 | 位置和职责 |
| --- | --- |
| Feature 入口 | 本目录 `README.md`，导航与当前状态，不复制完整合同 |
| 产品说明及细则 | `01-产品说明.md` 与必要专题；说明目标、用户行为、验收及实现差距 |
| 产品澄清 | `产品澄清.md`，一个问题一个负责 Feature；其他 Feature 引用同一稳定 PQ |
| 技术设计 | 本 Feature 的技术总设计或明确范围的专项；共同消费者不改变合同所有者 |
| 正式 Code Spec | 本 Feature 唯一 `Code-Spec.md`，持续更新，不按日期复制新当前版本 |
| 可选实施计划 | 本 Feature 唯一 `Implementation-Plan.md`，单独确认后作为任务账本 |
| 自测方案与记录 | 本 Feature `10-自测方案与执行记录.md`，实际批次绑定不可变版本追加 |
| 实施澄清 | 本 Feature `11-实施澄清记录.md`，工程取舍，不替代产品澄清或技术确认 |
| 历史检查与缺陷 | Review / Bug 保留原证据位置，只引用不复制 |

阶段门禁见[交付工作流](../agents/feature-delivery-workflow.md)，Spec/Plan 的通用要求见[合同规范](../superpowers/README.md)，自测见[公共规范](../validation/README.md)。产品、设计、Spec 的确认及代码实现、推送、部署、验证必须分别记录；已完成 Feature 不补造历史设计、确认或测试证据。

设计和 Spec 是可修订的长期合同，不是一次性产物；实质变化需要重新核对受影响范围。没有来源的需求标为待确认，不从现有代码倒推产品承诺。GitHub Issue 仍负责执行队列。
