# 固定串行执行｜产品说明

- Feature：11；适用版本：V1
- 整理日期：2026-09-29；复用既有固定链路，不增加执行模式
- 产品依据：[V1 固定团队执行](./03-执行交互与整体验收.md#p-63-团队负责人lead与固定团队执行)
- 交接依据：[编排器与执行状态](./02-执行状态与恢复.md#a-3-orchestrator-与执行状态)

## 背景

一次首次创建任务需要从需求形成可检查的设计、源码和验证结果。V1 采用固定顺序接力，让用户能知道当前正在做什么、前一步交付了什么，以及为什么暂时不能继续。

## 摘要

- **固定顺序**
  - 首次创建按 PM、Architect、Engineer 完整执行，再进入适用的构建、测试和校验。
- **真实交接**
  - 用户批准、上游产物和验证证据必须有效；阶段动画或模型自报不能代替这些条件。

## 从请求到结果

Lead 可以直接回答或澄清，也可以把明确创建请求交给团队。直接回答不创建团队执行、构建任务、Git 提交或项目版本，也不展示虚假的角色时间线；用户可显式要求调用团队。

首次创建进入团队后，依次完成产品方案、用户对当前方案的确认、架构设计、源码与测试，再由平台执行适用的验证。产品尚未批准、批准后内容改变或能力结论不支持时，不得进入架构阶段。架构和源码必须使用有效的上游依据；修复改变源码后，旧执行结果不能继续作为通过证据。

一个任务同一时刻只有一个主执行阶段。用户可以查看当前角色、阶段状态、实际产物、等待和失败原因；进度必须对应真实执行，不展示并行协作假象或模型私有推理。阶段输出应先保存，再报告完成，刷新或重连后的恢复目标沿用共同基线。

首次创建中，明确属于源码或单元测试的可修复失败最多允许一轮工程师自动修订，之后重新验证；仍失败或根因不明时停止并保留原因，不能无限返工或掩盖执行环境问题。停止、继续和取消沿用既有产品规则，不由此入口新增恢复方式；当前覆盖需要实际用例验证。

最终能否形成版本、是可运行还是仅源码就绪，由[Feature 07](../../05-产物与交付部署/07-通用源码与运行校验/01-产品说明.md)决定；没有匹配运行能力时不能伪造构建、测试或预览通过。发布不属于模型执行链，必须遵守独立发布规则。

## 与修改、规划和并行的关系

本功能定义首次创建的完整链路。[已有项目修改](../04-对话式代码修改/01-产品说明.md#5-lead-与下游团队如何分工)可以按已确认产品目标选择固定入口，复用有效上游结果并顺序执行剩余阶段，不能跳过批准、适用验证和版本保护。该入口选择尚未实现，技术方案和 Code Spec 仍需独立确认。

V1 不引入任意角色组合、任务图、并行执行或跨角色自动回退。先规划再按依赖执行属于后续编排范围，本次不将其变成新的 V1 承诺。

## 当前状态

共同设计已有固定三角色链路和本地验证的历史记录，实际环境验收仍依赖[执行服务](../../04-执行与验证环境/06-共享独立执行服务/01-产品说明.md)与相关交付证据。本次只整理入口，不把历史局部测试等同于整个执行、停止和恢复流程已经验收。
