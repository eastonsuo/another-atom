# 开发侧自测方案与执行记录规范

本文维护公共自测规范，回答“指定 Feature 的明确实现，在明确非生产环境和不可变版本上是否满足本次开发侧验收合同”。实际记录放在对应 [Feature 目录](../features/README.md)，本目录不保存各 Feature 的执行记录。部署健康、代码测试和环境功能验证是不同证据，不得相互替代。

## 1. 唯一记录

一个 Feature 只维护一份自测方案与执行记录，固定落点为：

```text
docs/features/<能力域编号>-<能力域名>/<稳定编号>-<中文功能名>/10-自测方案与执行记录.md
```

同一文件持续保存方案、部署批次、用例结果和开发侧结论。不要另建功能验收方案、部署验收记录或 Validation Handoff。

在编写方案或记录实际验证时按需创建，并与 Feature 入口双向链接；不为占位建立空记录，不补造已完成 Feature 的历史结果。既有 Review、Bug 或提交中的证据保留原位置并引用。没有对应 Feature 的普通维护修改只在实施摘要中交付本地证据。

## 2. 来源与范围

开发侧必测范围是以下三者的交集：

```text
用户确认的本次交付范围
∩ 已确认 Code Spec 中适用的验收合同
∩ 本次实现及其直接影响边界
```

记录必须链接唯一 Code Spec、适用技术总设计、代码提交和实际目标环境。超出开发责任边界的内容只记录为联调依赖或测试建议，不能混入必测通过结论。

### 测试层级与证明范围

按合同和风险选择测试层级，不要求每次修改机械覆盖全部层级：

| 层级 | 运行边界 | 可以证明什么 |
| --- | --- | --- |
| 组件／隔离测试 | 单个模块或组件，可用测试替身隔离相邻依赖 | 内部逻辑、分支、错误处理和局部合同 |
| 本地真实边界集成 | 本地或 CI 中通过真实入口、协议或存储连接本次合同涉及的真实组件 | 被实际运行的跨进程、跨服务、跨协议或依赖交互 |
| 部署后非生产端到端验证（E2E） | 已登记非生产环境的真实入口、服务、配置、网络与权限 | 只有实际部署能够证明的端到端行为 |

在真实边界集成和非生产 E2E 中，本次声称被验证的组件、协议和交互必须真实运行；合同范围外的外围依赖可以使用 Mock，但基于替身的结果（Mock-backed）不能关闭真实依赖的验收。跨组件合同应安排有意义且当前可执行的本地真实边界集成；部署配置、网络、权限或本地无法证明的合同进入非生产 E2E。两层证明不同风险时分别保留，不能用组件测试或本地通过替代未覆盖的环境边界。

本地测试装配不足时先复用仓库已有入口；仍不可执行时记录具体原因、未覆盖合同和后续验证入口，不写成通过。尚未部署只影响相应环境用例的 `NOT_RUN` 或 `BLOCKED` 状态，不阻止已满足实施条件的代码进入构建或部署，也不据此宣称环境验证已完成。

## 3. 记录结构

每份记录按实际内容保留：

1. Feature、Code Spec、交付范围与非目标；
2. 本地验证结果及其命令、时间和代码基线；
3. 执行批次：本地、CI 或已登记非生产环境，实际代码／不可变版本、关键配置、测试数据、真实或 Mock 依赖；环境批次另记主服务与 executor 的分别读回、入口与部署事实；
4. 用例：场景、测试层级、Fixture、操作、预期、失败判定、实际结果、执行主体、时间和证据；
5. 阻塞、未覆盖合同和责任入口；
6. 开发侧结论。

只记录实际执行的批次，不预建空批次或默认把本地测试设为首批。代码、镜像、配置、测试数据或依赖变化可能影响结果时，建立新批次重测受影响用例，不覆盖旧事实；未受影响用例可以引用原批次，但必须说明判断依据。旧基线的 `PASS` 不得直接写成新基线已通过。

## 4. 用例状态

- `PASS`：真实执行满足预期，且有可复核证据；
- `FAIL`：合同被真实执行，但实现结果违反预期；
- `BLOCKED`：环境、身份、凭证、工具、Fixture、依赖或版本问题使合同没有被有效执行；
- `NOT_RUN`：场景已纳入方案，但尚未执行。

只有当前不可变版本上的全部必测用例均为 `PASS`，才能记录“开发侧自测门禁满足”。这不等于测试人员正式验收或生产发布许可。

## 5. 职责边界

- `implement-code-change`：业务代码、测试、静态检查、前端 lint/build 和可执行的本地真实边界集成；
- `deploy-for-validation`：制品、部署、Rollout、健康、入口、实际版本读回、环境恢复；
- `validate-in-non-production`：自测方案、验证侧 Preflight、Smoke、API、页面、E2E、结果和开发侧结论。

产品缺陷返回代码实施；部署或环境问题返回部署处理；权威合同无法唯一决定预期时返回设计和 Code Spec。失败与重测追加记录，不能覆盖旧结果。
